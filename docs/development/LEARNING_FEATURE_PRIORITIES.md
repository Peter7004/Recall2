# Recall Reader 학습 기능 우선순위

검토일: 2026-11-03 (Asia/Seoul). 실제 코드와 개발 인계 기록을 기준으로 작성.
이 문서는 개발 순서 제안이며, 아래 완료 기준은 아직 통과한 테스트 결과가 아니다.
**P0 Reader 학습 저장 충돌 방지 완료**: 소스 bd3ee40, 웹·Android 테스트 APK CI 및 공개 웹 두 탭 검증 PASS.
세부 증거와 한계는 STORAGE_SAFETY_VERIFICATION.md를 참조한다. 후속 기능은 아직 구현하지 않았다.

## 판단 기준

1. 기존 사용자 기록 손실 방지가 가장 우선이다.
2. PDF 읽기 → 용어 저장 → 복습 → 정확한 원문 복귀를 먼저 완성한다.
3. 기존 사전·플래시카드·분류 UI를 재사용하고 작은 단위로 확장한다.
4. 단순 조회·카드 넘김과 실제 정답·암기 성과는 구분한다.
5. 오프라인 중심을 유지한다. AI, OCR, 계정, 서버, FSRS는 이번 범위에 추가하지 않는다.

일정으로 확정하지 않는다. P0 완료 전에는 학습 기록을 추가로 쓰는 기능을 확장하지 않는다.

## 단계별 완료 기준과 검증

### P0 — 저장 충돌 방지: 완료 기준 및 검증 범위

- 같은 프로세스의 독립 인스턴스와 협력하는 웹 탭의 쓰기를 직렬화하고,
  독점 구간 안에서 최신 저장값을 읽은 뒤 해당 변경만 적용한다.
- 오래된 스냅샷을 무조건 병합하지 않는다. 다른 곳에서 삭제한 기록이 다시 생기면 안 된다.
- 안전한 교차 탭 잠금을 제공할 수 없는 환경은 쓰기 실패를 안내하고 기존 데이터를 보존한다.
- 다른 인스턴스·탭의 변경을 반영한다. 기존 키와 JSON 호환성은 유지한다.
- 완료 기준: 동시 A/B 저장이 모두 유지되고, 오래된 인스턴스가 C를 저장해도 삭제된 A가
  부활하지 않음. 저장 실패·손상 JSON에서 이전 유효 기록을 덮어쓰지 않음.
- 검증: 독립 저장소 단위 테스트, 실제 브라우저 두 탭 저장/삭제/새로고침,
  실패 주입, 기존 저장·원문 복귀 회귀 테스트. Android 프로세스 간 다중 쓰기 보장은
  별도 검증 없이 주장하지 않는다.

### P1 — 데이터 일관성·복구·기기 안정성

- 정의: 사전 항목이 있으면 뜻·정의·설명을 모두 최신값으로 표시한다. 삭제된 항목은
  저장 스냅샷으로 표시하고 이를 안내한다. 과거 스냅샷은 사용자 동의 없이 삭제하지 않는다.
- 링크: 공통 접근 가능 여부 확인을 재사용하고, 누락·손상 문서는 이동을 비활성화한다.
  확인 이후 파일이 사라지는 경우도 이동 시 다시 오류 처리한다.
- 백업: 버전 있는 Reader 별도 형식으로 단어·출처 좌표·읽기 위치·페이지 북마크·설정을
  포함한다. 원본 PDF는 기본 제외하고, 복원 후 파일 재연결 필요성을 안내한다.
  문서 해시로 연결하고 같은 문자열만으로 출처를 식별하지 않는다.
- 복원은 먼저 전체 검증·변경 미리보기·병합/대체 정책 확정 후 적용한다. 같은 출처를
  두 번 복원해도 중복이 없어야 하며, P0의 저장 직렬화 규칙을 따라야 한다.
- 검증: 사전 수정/삭제 후 표시, 파일만 소실, 손상 백업·잘못된 버전·중복 복원·쓰기 실패,
  복원 전후 기록 수/좌표 비교. 여러 저장 키의 중간 실패가 부분 복원으로 남지 않도록 설계한다.
- 성능: 확보된 실제 PDF의 크기·쪽 수를 기록하고 가져오기/열기/검색 시간과 메모리를 측정한다.
  50MB·100MB·500쪽 및 제한/암호화 PDF가 없으면 NOT TESTED로 남긴다.
  웹 성공과 APK 빌드 성공은 Android 기기 성공으로 대체하지 않는다.

### P2 — 문서에서 복습으로 연결

- 문서별 복습은 등장 위치가 여러 개인 같은 사전 ID를 한 카드로 묶어 기존 `ReviewPage`에
  전달한다. 원문 출처 이동을 유지한다. 삭제된 카드·복습 제외 카드·빈 목록을 처리한다.
- 검색·정렬은 저장 단어/뜻/문서와 최신 저장순 등을 지원하되 기존 필터와 함께 작동한다.
- 오답 노트는 먼저 ‘기억함 / 다시 학습’ 같은 명시적인 사용자 평가로 저장한다.
  답 공개·다음 카드 이동을 정답으로 해석하지 않는다.
- 퀴즈는 평가 이벤트와 출제 집합을 기록하고, 중복 뜻·여러 정답 가능성을 처리한다.
  최초에는 사용자가 직접 판단하는 회상 평가를 제공할 수 있으며 이를 객관식 채점과 구분한다.
- 미등록 용어는 기존 직접 추가 폼을 재사용하되 입력 뜻·검토 상태·PDF 출처를 연결한다.
  확인하지 않은 뜻·정의는 자동 생성하지 않는다. 기존 공용 단어를 덮어쓰지 않는다.
- 출처 하나 삭제는 다른 출처와 사전 카드를 보존한다. 마지막 출처 삭제 시 단어 유지
  여부를 명확히 정하고 확인창에서 안내한다. 메모는 단어 정의와 분리한다.
- 검증: 여러 문서/동일 쪽 다중 위치, 중복 카드 방지, 삭제·재시작·평가 재저장,
  한 출처만 삭제, 원문 이동, 기존 사전·플래시카드 키 보존.

### P3/P4 — 학습 품질과 지속 사용

- 진도는 고유 단어 수와 평가 시도 수를 분리한다. 기존 오늘 완료 수의 의미를 바꾸지 않고
  새 지표를 설명한다. 자정·시간대·앱 재시작·중복 평가를 테스트한다.
- 분야 설정은 기존 과목과 필터를 재사용하고 과목 삭제 후 안전한 기본값으로 돌아간다.
- 랜덤 단어는 하루 동안 안정된 선택과 빈 분야 처리를 검증한다. 미등록 뜻을 만들지 않는다.
- 자동 주기는 기존 필드를 검토하되 기존 데이터를 임의로 초기화하지 않는다.
  단순 일정부터 도입하고 FSRS는 제외한다. 시계 주입 테스트로 기한 경계를 확인한다.
- TTS는 사용자 버튼으로만 실행한다. 음성 미설치·오프라인·지원되지 않는 플랫폼은 안내하고
  PDF 읽기를 방해하지 않는다. 새 패키지는 실제 필요·라이선스 검토 후 결정한다.
- 연속 일수는 ‘앱 실행’이 아닌 확정된 학습 이벤트를 기준으로 하고 날짜 중복 계산을 방지한다.
- 관련 용어는 현재의 정규화 링크를 유지하고 없는 항목은 열린 사전 항목처럼 표시하지 않는다.
- 오류 신고는 원문 PDF나 주변 문장을 자동 전송하지 않는다. 외부 전송 기능은 별도 범위다.

## 현재 범위와 남은 확인

- 이 문서는 코드 조사에 근거한 계획이다. 실제 실행 결과는 HANDOFF와 해당 검증 문서에
  PASS / FAIL / NOT TESTED로 따로 기록한다.
- 사용자 기기의 PDF·성능·TTS 음성 설치 상태는 코드만으로 확인할 수 없다.
- 백업 용량 제한, 복원 병합 기본값, 오답의 해제 기준, 퀴즈 형식은 해당 모듈 착수 시 구체화한다.
- 기존 사전 키 `recall.data.v3`와 Reader 키를 분리 유지한다. 전체 구조 교체나 데이터 삭제는
  이 우선순위 계획에 포함하지 않는다.
