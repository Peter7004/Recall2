# Reader 저장 충돌 방지 — 우선순위 P0 (2026-11-03)

## 선택 이유와 범위

새 학습 기능을 추가하기 전에 기존 학습 기록의 유실·삭제 기록 부활을 막는다.
이미지의 10개 기능과 추가 제안 전체 순위는 LEARNING_FEATURE_PRIORITIES.md에 정리했다.
이번 모듈은 Reader 저장 안전성과 자동 단어 북마크 연결의 안전한 실패를 구현한다.
백업·복원, 정의 표시·파일 접근 판정 일관성, 오답·퀴즈는 다음 우선순위다.

## 구현

- 기존 `recall.reader.learning.v1` 키와 버전 1 스키마를 그대로 읽고 쓴다.
  마이그레이션, 빈 데이터 초기화, 기존 키 삭제 및 새 앱 의존성은 없다.
- 네이티브 UI isolate의 Reader 인스턴스는 공통 큐를 사용한다. 웹은 origin에
  공통인 이름의 배타 Web Lock으로 읽기→변경→영구 저장 전체를 보호한다.
  [Web Locks 표준](https://www.w3.org/TR/web-locks/)과 설치된 web 1.1.1 API를 확인했다.
- 잠금을 확보한 뒤 SharedPreferences를 reload하고 최신 스냅샷으로 의도한
  저장/삭제만 수행한다. 오래된 전체 스냅샷을 병합해서 삭제된 기록을 되살리지 않는다.
- 성공한 변경은 같은 화면 프로세스와 웹 storage 이벤트로 다른 열린 목록에 반영한다.
  갱신 실패 시 마지막 정상 상태를 유지하고 재읽기 안내를 표시한다.
- 웹에서 안전한 잠금을 지원하지 않으면 읽기는 허용하고 쓰기는 명시적으로 거부한다.
  잠금 대기는 15초 후 취소하고 무잠금 저장으로 대체하지 않는다.
- Reader의 기존 사전 북마크 연결도 같은 잠금 안에서 실행한다. 기존 사전이
  외부에서 변경됐다면 오래된 상태로 덮어쓰지 않고 부분 성공을 안내한다.
  사전의 로딩/자체 저장/백업 복원 시 마지막 영구 문자열을 추적한다.
- 닫힌 화면의 구독을 해제한다. 이미 요청된 저장은 완료하되 닫힌 화면에 알리지 않는다.

## 보장하지 않는 범위

- 기존에 열어 둔 구버전 앱 코드는 이 잠금을 사용하지 않는다. 모든 Recall 탭을
  새로고침한 뒤 신버전 동시 저장을 사용해야 한다. 구버전의 임의 쓰기는 통제하지 못한다.
- 일반 사전 편집 전체의 다중 탭 직렬화는 이번 변경에 포함하지 않았다.
  Reader 자동 북마크 연결은 협력하는 잠금과 오래된 사전 검사로 보호한다.
- 네이티브 공통 큐는 현재 앱의 UI isolate 범위다. 별도 엔진/백그라운드 프로세스
  쓰기는 도입 전 별도 원자 저장 설계가 필요하다.
- 브라우저 데이터 삭제·앱 제거에 대한 백업은 아니다. Reader 백업은 다음 단계다.
- Android APK 빌드 성공과 실제 기기 성공을 구분한다. 영구 서명 배포 APK는 변경하지 않는다.

GitHub 전체 테스트/배포 및 공개 웹 확인은 정확한 소스 SHA와 실행 번호로
HANDOFF.md에 이어 기록한다. 완료 전에는 성공으로 추정하지 않는다.
