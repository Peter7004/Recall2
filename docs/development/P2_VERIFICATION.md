# P2 문서 보관·PC 호버 하이라이트 검증 (2026-11-02)

## 구현 결과

- 최근 문서 목록, 제목 검색·변경, 중복 PDF 감지, 재실행 후 관리 복사본 열기.
- 이름이 아닌 전체 내용 SHA-256으로 문서를 구분한다. 기존 읽기 위치 키를
  재사용하므로 예전 사용자가 같은 PDF를 처음 보관할 때도 읽던 위치를 복원한다.
- Android는 `noBackupFilesDir/recall_reader`에 PDF와 메타데이터를 보관한다.
  기존 사전 백업을 비활성화하지 않는다. 백업 제외의 근거:
  [Android 공식 문서](https://developer.android.com/identity/data/autobackup).
  실제 Android 백업·복원 실험은 아직 NOT TESTED이다.
- 기타 네이티브는 application support 폴더를 사용한다. 앱 전용 디렉터리에
  PDF와 메타데이터를 작성한 다음 공개하며, 제목 변경은 메타데이터만 갱신한다.
- 웹은 IndexedDB의 documents/bytes 저장소를 사용한다. 가져오기·삭제는 두
  저장소를 포함하는 트랜잭션으로 처리하고 목록 조회는 PDF 바이트를 읽지 않는다.
- 삭제 확인창에서 범위를 안내한다. 관리 문서와 마지막 읽기 위치만 삭제하고
  원본 PDF와 단어·북마크·플래시카드는 유지한다. 문서 삭제 실패 시 읽기 위치를
  복원한다. 네이티브 잔여 파일 정리에 실패하면 알리고 다음 목록 조회에서 재시도한다.
- `path_provider`와 `web`은 이미 설치되어 있던 버전을 직접 의존성으로 선언했다.
  버전 업그레이드, 서버·계정·외부 AI API·OCR·광고 SDK 추가는 없다.

## 요청한 PC 호버 동작

마우스를 사전에 등록된 단어/복합 용어 위로 이동하면 해당 발생 위치의 실제
PDF 텍스트 조각만 노란색으로 강조한다. 줄이 나뉜 용어의 각 조각을 처리하고,
커서가 벗어나거나 보기 위치가 바뀌거나 선택을 시작하면 해제한다. 문서나 사전을
수정하지 않으며 기존 드래그 선택·뜻 팝업·검색 강조 표시를 유지한다.

이미지 속 글자·스캔 PDF·사전에 없는 단어는 자동 강조하지 않는다. PDF의 복사
제한 플래그를 존중한다. 매칭은 현재 기존 사전의 문자열/경계/복합어 우선 규칙을
사용하므로 미등록 변형이나 불완전한 PDF 텍스트 인코딩은 인식하지 못할 수 있다.

## 재현 도구

- `tool/reader_library_smoke.cjs`: 외부 Playwright와 실제 매뉴얼 두 개 필요.
  `RECALL_PLAYWRIGHT_MODULE`, `RECALL_READER_TEST_URL`, 필요 시
  `RECALL_PDF_FIXTURE_DIR` 설정. 출력: build/reader-library-smoke.
- `tool/check_reader_hover.py`: Pillow로 위 스크린샷의 실제 강조·해제를 확인.
- `tool/reader_navigation_smoke.cjs`: 문서 목록 버튼이 추가된 UI에 맞춰 갱신.
- 테스트 PDF는 output/pdf/Recall_User_Manual_v1.0.2_ko.pdf와 v1.0.3이며,
  대용량 또는 스캔 PDF를 테스트한 것으로 간주하지 않는다.

브라우저 데이터 삭제/저장 공간 회수 또는 앱 삭제 시 관리 복사본이 사라질 수
있다. 원본은 별도로 보관해야 한다. 현재 파일 선택/뷰어는 여전히 PDF 전체를
메모리에 읽으므로 대용량 성능은 후속 검증 대상이다. 영구 하이라이트, 페이지
북마크, 단어 저장·원문 연결, 최근 위치로 뒤로 가기는 다음 개발 단계이다.
